bump: minor

Log now supports advancing and manually completing a recovery block: complete a week before adding the next one, attach a new or existing note as each sequential week, unlink the latest week, complete the whole block, and browse completed blocks in a collapsible history. Completing a block with its open current week, and deleting a linked recovery-week note, are now crash-safe: each records its intent before writing, verifies the result against stored data, and resumes automatically after an interrupted attempt, an app restart, or a sync. Adding a week with a brand-new note is covered the same way, so a double tap or an interrupted attempt can never create a duplicate note or skip a week number; if another device took that week number first the week is renumbered and finishes on retry, and if the change has become impossible Log explains it once instead of leaving recovery stuck. A cloud sync can no longer run at the same time as one of these changes, so neither can overwrite the other. If a change cannot be finished yet it is shown as pending with a Retry recovery action instead of being reported as done, and a pending change never leaves a recovery week pointing at a deleted note or a deletion that never reaches the cloud after signing in.
